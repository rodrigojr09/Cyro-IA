# Cyro 9.0.1

Códigos e comandos agora são executados em um serviço separado no backend, com
área privada persistente por EV. Docker deixa de ser requisito no computador.
O Desktop confirma o pedido e envia apenas projectId/requestId; código e arquivos
vêm do snapshot autorizado da API. Resultados enviados pelo cliente são recusados.

Cada execução usa sandbox temporário sem rede, credenciais ou acesso a outros EVs,
com limites de CPU, RAM, disco, processos, tempo e saída. Os arquivos UTF-8 gerados
retornam à IDE; edições concorrentes são preservadas e informadas como conflitos.
Recibos impedem repetir comandos ao consultar resultados. Nova execução cria novo pedido.

SDK 0.1.5 e portal Dev 0.4.1 documentam o contrato. A API permanece compatível
com EV API 1. Memória, conversas, anexos e instalador 9.0.0 são preservados.

**Infraestrutura:** o operador deve implantar o runner privado e configurar
CYRO_EV_RUNNER_URL/CYRO_EV_RUNNER_SECRET na API. Instruções no backend,
services/ev-runner/README.md. Sem essa configuração, a execução retorna 503 claro;
não há alternativa local nem execução no processo principal da API.

aprovados. Cinco testes focados do runner também aprovados após persistência com fsync.
Desktop: 190 testes JS, 223 Python, 31 de empacotamento, 4 de plataforma e oito
cenários Electron. Portal: três testes e build. SDK: nove testes e igualdade dos
pacotes distribuídos com a instalação na API.

Instalador auditado: `release/v9/Cyro-IA-Setup-9.0.1.exe`, 144.073.159 bytes,
ProductVersion 9.0.1, sem assinatura Authenticode. SHA256:
`373ec42cb99cca48d55e1f3c97e5c2ae28f21b8d3eff7f4519b27566a97320c7`.
Payload iniciou duas vezes com perfil temporário e PATH sem Python/Node, mantendo
persistência após reinício. Não é homologação em Windows limpo. O instalador 9.0.0
permanece com seu SHA256 original.

`serverExecutionConfigured=false`: o serviço runner ainda precisa ser implantado
e configurado no Coolify. Nenhuma execução real de usuário foi enviada à produção.
