# JARVIS 4.2.0

Publicação e compilação autorizadas pelo proprietário em 23/10/2026.
Cloud: `https://cronosjarvis.vercel.app`; repositório privado
`rodrigojr09/Jarvis`, branch `master`.

## Alterações finais da v4

- Até cinco anexos por mensagem, com até 5 MiB cada, validação no Desktop e no
  backend. Originais ficam locais; o Cloud recebe conteúdo transitório para
  análise e guarda apenas a quantidade de anexos no histórico. Em outra máquina:
  “Salvo localmente em outro Computador”.
- Configurações simplificadas, consumo de armazenamento local e Cloud e limpezas
  separadas, com confirmação nativa e preservação das pastas originais.
- Cota Cloud padrão de 50 MiB por usuário, ajustável pelo administrador dentro
  do seu escopo. Bloqueio de novas consultas com orientação para apagar chats;
  acesso ao histórico e à limpeza permanece disponível.
- Nome e instruções de chat separados das configurações do projeto. Chats de
  projeto recebem as instruções do projeto e suas orientações adicionais.
- Menu de contexto na sidebar; aba Chats arquivados com restauração; arquivados
  não aparecem na sidebar. Diálogos fecham após ações concluídas.
- Site público removido; login individual protegido, Quick Chat fixo, projetos
  e seus chats locais e encerramento ao fechar a janela continuam preservados.

Detalhes em [ATTACHMENTS.md](ATTACHMENTS.md) e
[STORAGE-SETTINGS.md](STORAGE-SETTINGS.md).

## Processo de validação

O pipeline executa testes Cloud, iniciadores, TypeScript, build Next.js, testes
Node e Python, quatro verificações no Electron real, PyInstaller, NSIS e
auditoria do ASAR/runtime. O backend compilado possui self-check dos leitores de
imagens e PDF. O payload deve iniciar duas vezes com dados temporários e PATH
restrito, sem Node/Python externos, preservando o estado local após reinício.

As migrations aditivas necessárias são
`20261022150000_local_attachment_notice` e
`20261023100000_storage_settings`. Nenhum reset de dados é necessário.

Chamadas de IA/áudio nos testes são simuladas; isso não comprova consumo pago
em produção. A máquina de desenvolvimento não equivale a Windows limpo. O
instalador não possui certificado de assinatura configurado. Não foi criada
tag de release.

Artefato previsto: `release/v4/JARVIS-Setup-4.2.0.exe`, acompanhado de SHA-256.
O checksum, os metadados do instalador e a confirmação de publicação pelo SHA
do commit ficam no recibo local `release/v4/VALIDATION-4.2.0.json`, gerado após
as verificações finais.

## Testes da versão final

Pipeline 4.2.0 aprovado nas etapas anteriores ao empacotamento: 24 testes Cloud,
25 testes de inicialização/build, TypeScript, compilação Next.js, 84 testes
Node Desktop, 112 testes Python relacionados ao Cloud/projetos e quatro testes
no Electron real. O painel administrativo também passou por 35 verificações
de layout com dados sintéticos em Chromium real.

O npm ci da raiz concluiu com 483 pacotes instalados e zero vulnerabilidades
reportadas. Nenhuma chamada paga de IA/áudio foi usada como prova de validação.
O backend 4.2.0 compilado passou no self-check de imagens/PDF com PATH restrito.
